# Точный стек в автономном ядре

11.10.2026. Реализован opponent_stack.hpp и подключён к Behavior.

ExactOpponentStack содержит HP/armor, подтверждение источника, ID соперника/матча/карты, поколение респауна и время. Сопоставление обязательно с текущим StackContext и opponent_id Observation. Просроченные (по умолчанию старше250мс), будущие, неподтверждённые, мёртвые или чужие записи не используются. Никаких скрытых координат в контракте нет. Эти значения/TTL пока инженерные начальные параметры, не измеренная частота сенсора.

При подтверждённых правилах поглощения бронёй вычисляется непрерывный бюджет входящего урона H + min(A, H*r/(1-r)). Это приблизительная оценка стойкости, а не точное число выстрелов до убийства: дискретное округление/тип урона/геометрия не моделируются. Для r=2/3 стек10/200 даёт около30, а не210. Неверные правила не используются.

Если бюджет соперника минимум в1.15 раза выше, нормальный режим выбирает Recover и YellowHealth с существующим ранжированием маршрутов к ресурсам. Если собственный бюджет минимум в1.15 раза выше, он заменяет внешний favorable_fight_estimate для существующих проверок пуша. Порог1.15 — предварительный консервативный параметр, точность оружия не меняется. Равенство не даёт автоматического преимущества. Точный стек сам по себе не разрешает атаку/пуш невидимой цели и не отменяет opening, damage threshold, стиль или состояния тильта/pressure escape.

Перчаточная месть может использовать свежий точный HP вместо старой оценки, но продолжает требовать видимость, близкий безопасный контакт и остальные условия. Диагностика Decision включает exact_stack_used и оба бюджета. Если точного стека нет, сохраняется прежний оценочный вход, а не нулевой стек врага.

Проверки: MSVC Debug успешен,11/11 групп CTest прошли. Новые сценарии: сильный враг отменяет favourable flag и выбирает YA; слабый враг позволяет видимый push; невидимость не разрешает push; старый/будущий/неподтверждённый стек, другая жизнь и матч отвергаются; неизвестные/некорректные armor rules не принимаются; лишняя броня при малом HP не суммируется целиком.

Граница: это исполняемая локальная политика, НЕ подключённое серверное считывание HP/armor. Выбран target_item, но маршрут QL и подбор ещё не исполнены. Полный реестр точных таймеров всех итемов остаётся следующим модулем; существующий ItemMemory поддерживает отдельные точные записи. Серверы не изменялись.
