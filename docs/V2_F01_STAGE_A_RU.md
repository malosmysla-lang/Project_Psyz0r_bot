# V2-F01-A — код и данные, 19.11.2026

Это первый локальный подэтап V2.0.0-red_rj_instruction, а не приёмка всего F01.

## Исправленный дефект

Старый исполнитель мог закончить ресурсный RJ после приземления выше исходной
точки либо после любого недавнего подбора. Для красного это создавало ложный
успех: бот оказывался наверху, но целевую броню не получал.

Теперь в начале попытки фиксируются целевой entity и слот инициировавшего бота.
Только реальный pickup этого entity этим ботом подтверждает успех. Событие
сохраняется независимо от дальнейшей смены цели или другого подбора. Отсекаются
события до попытки, из будущего и после конечного окна посадки. Посадка без цели
заканчивается `outcome=target_not_picked`, а не успехом. Высота сохраняется как
отдельная диагностика.

Анализатор и sweep-счётчик также исправлены: новый неудачный результат с `higher=1`
не увеличивает число успешных подборов. Историческая трактовка старых логов
помечена отдельно; для V2 есть счётчик `verified_target_pickup_successes`.

## Новые данные

Для Blood Run выбраны 267 уникальных записей с владельцем, AGENT или PsyRoZ.
Извлечены 265 dm_91; два других протокола сохранены, но неподдерживаемым парсером
не обработаны. Наблюдаемый клиент определяется по game state, слоту и временному
интервалу имени. Имя автора файла или зрителя не присваивается наблюдаемому игроку.

Подборы красного: nekitz0r 803, AGENT 321, PsyRoZ 9. Детектор нашёл 321 кандидат
rocket-boost и пять plasma-boost последовательностей перед подбором. Совпадение
выстрела, потери ресурса и импульса не доказывает владельца взрывного урона.

После проверки непрерывности, наблюдаемого отрыва от земли и подъёма к площадке
сформированы [38 кандидатов](training/V2_RED_CANDIDATES.json): 36 RJ и два
plasma-кластера. 11 кластеров имеют >=10 повторных наблюдаемых подборов.
Это группы по близким стартовым зонам, а не доказательство оптимальности маршрута.
Каждый образец сохраняет одну настоящую траекторию: усреднённый несуществующий
набор координат/углов в executor не подставляется.

В четырёх plasma-подъёмах начало находится около нижней площадки z≈408,
подбор — около z≈537. Один первичный plasma-кандидат с выстрелом сверху
исключён из обучения подъёму: наличие plasma перед подбором не доказывает plasma jump.

Из всех 142 найденных записей с участием владельца и Xaero извлечены snapshots.
Разбор scoreboard: 130 подходящих результатов, из них 75 завершённых и 55
незавершённых/forfeit; 11 дополнительных кандидатов только по имени файла
не превращены в подтверждённые результаты. Разные карты анализируются отдельно.
Агрегаты accuracy взвешиваются через сумму hits/shots; неизвестные подборы не нули.

## Граница результата и следующий подэтап

legacy PreAlpha не изменены. Исправление диагностического успеха само по себе
не объясняет все причины слабого контроля красного и не включает движение.

пробы каждого способа: обычный маршрут, телепорт, RJ и plasma. Банк не включается

остаются false до испытания.

Ситуационные комбо, месть, ранний FF и обучаемая адаптация этим подэтапом не реализованы.

## Воспроизведение

Использовать сохранённый intake с SHA-манифестом, PARSED_DEMOS и проверенными
демозаписями; UDT.dll передать явным аргументом. Команды:

```text
python tools/audit_red_v2.py --intake INTAKE --dll UDT_DLL --output RED_EVIDENCE
python tools/build_red_candidates_v2.py RED_EVIDENCE --output docs/training/V2_RED_CANDIDATES.json
python tools/audit_red_v2.py --intake INTAKE --dll UDT_DLL --output XAERO_EVIDENCE --maps * --players nekitz0r --opponent Xaero --snapshot-cache RED_EVIDENCE
python tools/summarize_xaero_v2.py INTAKE --output XAERO_EVIDENCE/SCOREBOARD_ANALYSIS.private.json
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1
python -X utf8 -m unittest discover -s tests -v
```

В shell, разворачивающем `*`, аргумент всех карт заключить в кавычки. Сырые
записи, snapshots, чат и private-отчёты сохраняются локально и не входят в Git.
