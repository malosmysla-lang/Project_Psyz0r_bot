# Наблюдатель штатной предметной цели — первый код связки QL

11.10.2026. По прямой команде владельца начато локальное программирование. Серверы не запускались/не изменялись. Это диагностический этап P0, не готовая подмена цели.

## Реализовано

- adapter/native/psyz_stock_goal_observer.h оборачивает исследованную функцию qagame+0x2c920. Единственный вызов оригинала получает те же state/travel_flags/output и возвращает неизменённый результат. Наблюдатель не меняет bot_state, цель или команды движения.
- После успешного вызова записывается ограниченный префикс результата — 48 байт в hex. Не читаем произвольные поля bot_state и не приводим результат к структуре Q3. Один диагностический вывод на 16 успешных вызовов, глобально для наблюдателя.
- Лабораторные ограничения: PSYZ_CONTROL_LAB (существующий установщик), PSYZ_STOCK_GOAL_OBSERVER=1, qlx_psyzTestInstance=1, net_port=27961, qlx_psyzControlMode=3. По умолчанию выключено. Наблюдатель устанавливается только при загрузке лаборатории с этими параметрами; изменение mode позднее не устанавливает отсутствующий hook.
- Перед установкой проверяется 16-байтовая сигнатура функции. tools/prepare_control_lab.py теперь обязательно принимает --qagame и проверяет полный SHA256 до изменения checkout. Проверяемый файл должен быть именно тем модулем, который впоследствии загрузит лаборатория; подготовка не проверяет будущую замену файла после проверки. Это не универсальный загрузчик и не защита от произвольной смены сборки.
- Подготовщик копирует оба наших header в отдельный checkout minqlx. Повторная подготовка не дублирует включения/вызов установщика.
- tools/read_stock_goal_log.py декодирует журнал. Первые три float и следующий int показываются только как candidate_origin/candidate_area по гипотезе Q3-подобного префикса. layout_verified=false и ready_for_execution=false сохраняются всегда. Неправдоподобные float не принимаются как координаты.

## Что ещё не подтверждено

Сигнатура функции и доступный префикс выбраны по дизассемблированию конкретного файла, но реальное Linux-подключение ещё не испытано. Наблюдение использует гипотезу о контракте вывода; неправильно восстановленный ABI может приводить к сбою даже при отсутствии записей в цель, поэтому код предназначен только для отдельной лаборатории.

Запись содержит opaque state token, не подтверждённый client slot. Токен годится для группировки внутри процесса; не является идентичностью игрока и не сохраняется между запусками. В журнале пока нет точного server timestamp для каждого goal-вызова и событий подбора. Не объявлять совпадения с соседними строками PSYZ_NAV точной временной привязкой.

Полный размер цели, ID предмета, связь с bot slot, LTG/NBG и подтверждение собственного подбора ещё требуют игрового исследования. 48 байт — диагностический префикс, не полная восстановленная структура. Никакой записи новой цели, программного обучения маршрутам или изменения точности этот этап не включает.

## Локальные проверки

MSVC Debug сборка успешна; CTest10/10 групп прошли. Новая stock_goal_observer_contract проверяет opt-out, отказ на основном порту, отсутствие маркировки, неправильный режим/отсутствующие cvars, несовпадение сигнатуры, отказ Hook, повторный install, ровно один исходный вызов, сохранение аргументов/результата/буферов, null/неуспех и отключённый журнал.

Разборщик:5/5 Python-тестов, включая ошибочный/усечённый вывод и нечисловые координаты. Отдельная проверка подготовщика на временном checkout: неправильный SHA не меняет hooks.c; правильный файл проходит; повторная подготовка идемпотентна; header скопирован побайтово.

Тесты подменяют minqlx Hook/cvars и исходную функцию стендовыми реализациями. Они подтверждают наш контракт, не реальный ABI и не Linux hook trampoline. Предыдущие9 групп ядра также прошли; код поведенческого ядра не изменялся.
