## Что действительно происходит

Режим qlx_psyzControlMode=3 не заменяет usercmd: штатный серверный AI пользуется своей AAS-навигацией. Наш native hook записывает собственное состояние bot slot0 после физической обработки каждые200мс: время, координаты, скорость, yaw, оружие, здоровье и землю. Позиции других игроков не читаются. Не выдавать штатную навигацию за обученный нами контроллер.

## Первый снимок данных

out/control_lab/navigation_pass.log:370 отсчётов за73800мс. docs/training/Bloodrun_navigation_observed.json:212 посещённых пространственных ячеек и262 разных направленных перехода. Это не212 комнат и не процент изученности карты.

Ячейки64×64 по XY и32 по Z; сохранена первая наблюдаемая точка, а не выдуманный центр проходимой области. Рёбра возникают только между последовательными наблюдениями при интервале до400мс и перемещении до256 единиц. Обратное ребро не добавляется автоматически. Разрывы времени/скачки не считаются найденным проходом.

Повторные рёбра сохраняют минимальную наблюдавшуюся длительность пребывания в исходной ячейке до выхода. Dijkstra выдаёт кандидата по сумме этих затрат. Стоимость зависит от дискретизации и ожиданий; не объявлять её оптимальным временем между точными позициями.

## Что ещё отсутствует

Пространственная ячейка может объединить точки по разные стороны тонкой стены. Граф не является проверенным navmesh, ready_for_execution=false. Для выбранной цепочки нужны проверка геометрии, непрерывный маршрут и повторное измерение движения. Нет команды самостоятельного обследования фронтира, активного поиска углов или анализа застреваний с доказанным намерением двигаться; неподвижность сама по себе не считается застреванием.

Этот проход — базовая запись проходимости штатного бота. Далее сопоставить с демкой владельца, выделить отсутствующие подходы, выбрать несколько пар старт/цель и проверить собственным MovementController. Пока наш исполнитель не использует этот граф для live движения.
