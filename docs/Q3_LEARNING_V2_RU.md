# Проверка обучения Quake III — 19.11.2026

Проверены исходники id Software, а не пересказ о Nightmare. В
[ai_main.c](https://github.com/id-Software/Quake-III-Arena/blob/master/code/game/ai_main.c)
`BotInterbreedBots` оценивает популяцию ботов через `kills * 2 - deaths`, выбирает
родителей/заменяемого кандидата, вызывает скрещивание goal fuzzy logic и мутацию.
`BotInterbreedEndMatch` запускает это по циклу матчей, если interbreeding включён;
`BotWriteInterbreeded` сохраняет конфигурацию лучшего кандидата.

[be_ai_gen.c](https://github.com/id-Software/Quake-III-Arena/blob/master/code/botlib/be_ai_gen.c)
содержит отбор родителей и потомка по оценкам. Требуется как минимум три допустимых
кандидата. Это отбор параметров популяции по игровому результату, а не извлечение
координат RJ человека из демки.

В [be_ai_weight.c](https://github.com/id-Software/Quake-III-Arena/blob/master/code/botlib/be_ai_weight.c)
`EvolveWeightConfig` изменяет balance-веса; `InterbreedWeightConfigs` скрещивает
совместимые деревья весов. Наблюдение движения/клавиш человека в этих функциях
не реализовано. Поэтому гипотеза «этот штатный механизм копировал движения людей»
проверенными функциями не подтверждается. Это не вывод обо всех сторонних модах.

## Что применимо к Psyz0r

Нужны два разных конвейера:

1. **Из человеческих демок:** измеренные траектории и успешные подходы → проверка
   геометрии/физики → управляемое исполнение и реальные подборы.
2. **Адаптация:** допустимые признаки соперника → обучаемая оценка/выбор проверенных
   действий → оценка на отложенных матчах и сохранение версии параметров.

Можно исследовать ограниченный подбор весов целей по аналогии с Q3, но обучать
«успешность прыжка» по одному приземлению выше старта нельзя. Новый V2-код требует
фактического подбора целевого предмета нужным ботом.

Код id Software имеет GPL; реализации в MIT-ядро не переносились. Проверен смысл
алгоритмов; подключённого автоматического Q3 learner в Quake Live этот этап не создаёт.
