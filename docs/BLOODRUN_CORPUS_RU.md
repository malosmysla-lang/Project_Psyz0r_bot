## Обработка

UDT1.3.1 проверяет gameStates/mapname. Собственный экспортёр сохраняет координаты, скорости, взгляд, оружие, HP/броню, события и pm_flags. Экспорт подходит для офлайн-разбора; исходные WASD/mouse не объявляются доступными.

Извлекается только записанный POV/игрок, за которым следит камера; это не одновременные полные траектории обоих соперников.

Для записей наблюдателя принимаются только состояния следования за игроком (pm_type2 + PMF_FOLLOW4096), а свободная камера и intermission исключаются. Флаг соответствует исходнику WolfcamQL code/game/bg_public.h, проверен на фактических снимках архива. При смене POV/сегмента, разрыве времени, смерти или скачке позиции цепочка обрывается. Обычные состояния pm_type0 принимаются отдельно.

Подборы декодируются по событиям UDT и protocol item ID. Для каждого подбора сохраняется окно до3 секунд непрерывного движения: это **финальный подход к предмету**, не полный путь через карту. Положение игрока при подборе не выдаётся за точную координату сущности предмета.

Сжатые снимки и подходы находятся в out/bloodrun_corpus/<ID>/ и out/owner_bloodrun_corpus/<ID>/. Реестр и итоговые количества — BLOODRUN_CORPUS_SUMMARY.json. Результат обучения пока библиотека наблюдений; геометрия/физика не утверждены, ready_for_execution=false. Загрузка и разбор сами по себе не добавляют навыка в игровой runtime.

## Применение дальше

1. Сгруппировать повторяемые финальные подходы к предметам и выделить полные непрерывные маршруты из снимков.
2. Сопоставить высоты/площадки с геометрией Blood Run; не соединять соседние координаты через стены.
3. Сравнить время только при сопоставимых старте/цели/физике; не объявлять короткое окно самым быстрым полным маршрутом.
4. Подключить один проверенный наземный маршрут к MovementController/native, подтвердить достижение цели и подбор, затем расширять.
5. Отложенные тестовые данные отделять по матчам, не только по файлам: разные POV одной дуэли иначе дают утечку проверки.

Точность стрельбы не менялась. Нейросеть не добавлялась. Штатный серверный навигационный проход не заменяет примеры игроков: база маршрутов формируется прежде всего из демок по команде владельца.
