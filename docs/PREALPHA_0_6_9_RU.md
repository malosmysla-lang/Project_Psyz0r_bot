## Что было неверно в таймингах

До изменения скрытые предметы участвовали в выборе только за 3 секунды до `nextthink`; время пути не учитывалось. Навигационная цель могла удерживаться до 30 секунд. Это не был обещанный полный план контроля по всем таймерам.

Новый `qlx_psyzItemTiming=1` включает реестр всех текущих item entities: доступность, ближайший срок из engine `nextthink`, время обновления. Предмет с неизвестным сроком не объявляется доступным. В промежуточной серверной проверке наблюдались 44 предмета без неизвестных сроков; Мега после подбора имела срок +35 000 мс.

Для Меги/красного горизонт планирования теперь до 15 секунд с условием `оставшееся время <= оценка пути + 3 секунды`. Оценка пути пока грубая: расстояние/300 + 2 секунды; это не AAS travel cost. Штраф ожидания учитывает время, которое остаётся после предполагаемого прихода. Возможность забрать основной предмет может перебить старое удержание цели у достаточно вооружённого бота с HP не ниже 70. Дебют, экстренное восстановление и ближайшая отсутствующая основная пушка сохраняют свои ограничения.

Сроки доступны по разрешённой владельцем модели обсерверских предметов; координаты скрытого соперника не используются. `nextthink` — время серверного callback, поэтому диагностика сохраняет источник, а фактическая доступность обновляется из игры. Проверка не распространяется автоматически на иные моды и нестандартные правила появления.

## Почему красный пропадал из маршрутного реестра

В финальной диагностике установлено: игровое отображаемое имя — **Red Armor**, а botlib ищет **Heavy Armor**. Запрос по отображаемому имени не давал цель после сброса карты; позднее она иногда появлялась через штатный выбор AI. Для `item_armor_body` теперь явно используется имя botlib. Зафиксирован ответ: `query=Heavy Armor result=29 area=1429`.

Дополнительно статический stock goal сопоставляется с текущим предметом по имени/позиции при сменившемся entitynum. Для несовпадающих номеров требуется расстояние менее 16 единиц, чтобы не путать близкие шарды. Настоящие AAS area и номер предмета botlib сохраняются, пути не выдумываются.

## Дебюты теперь исполняются иначе

- Старт фиксируется при переходе в матч; выбор варианта больше не сдвигается из-за первых шагов бота.
- Проверяется наличие всех целей последовательности; на готовность реестра даётся короткое окно до 2 секунд.
- Из 36 исходных наблюдений четыре варианта без основных пушек исключены из исполнительного выбора; данные сохранены. Доступны 32 кандидата.
- Среди близких наблюдаемых вариантов предпочтение получают старты с основной пушкой; это эвристика, не доказательство оптимального дебюта.
- Превышение стека соперника на 15% само по себе больше не отменяет весь дебют. Экстренное восстановление при низком собственном стеке, смерть, недоступность предмета и лимит 30 секунд по-прежнему отменяют план.
- Продвижение по шагам подтверждается реальным подбором, а не прибытием в приблизительную точку.

Аудит всех 36 вариантов: 100 назначений совпадают с предметами карты. Для 39 переходов старт подходит к существующему демо-маршруту в радиусе 97 единиц; 61 переход использует штатный AAS. Последовательность предметов и запись полноценного непрерывного пути — разные вещи; все пути и все респауны не объявляются проверенными.
