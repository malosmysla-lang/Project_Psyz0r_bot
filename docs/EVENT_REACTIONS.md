# События, чат и действия — 2026-10-09

Реализована локальная политика решений. Игровой исполнитель usercmd и сенсоры ударов/трупов пока не реализованы. Проверка в CTest и воспроизведение журнала не доказывают работу в Quake Live. На сервер на этом этапе ничего не загружалось.

## Перчатка

`GauntletDamage` принимается только с `verified=true`, непустым источником и стабильным ID соперника. Значение amount — подтверждённый урон по соглашению будущего сенсора, **не подтверждённая потеря HP**: учёт брони ещё требует проверки. Не получать amount из разницы общих damage_taken и текущего выбранного оружия: это не устанавливает источник урона.

Урон накапливается отдельно по соперникам между столкновениями. Порог `gauntlet_damage=50`, длительность `gauntlet_duration=90`; для тестов порог можно поставить 25. При включении цели накопитель расходуется. Последующие удары во время цели не продлевают её на каждом кадре. Завершение — подтверждённое убийство именно этого соперника Gauntlet, либо истечение срока. Убийство ракетой, другого соперника и один промах цель не завершают.

Обязательная попытка добивания требует: живой бот, LOS+FOV соперника, безопасный близкий контакт, достаточные собственные HP, рабочая перчатка и обоснованная оценка HP соперника не выше `revenge_target_estimated_hp=50`. Скрытые точные HP не используются. Тильт, pressure_escape и восстановление приоритетнее мести.

`revenge_contact_distance=64` — предварительный фильтр расстояния между позициями, **не доказанный радиус удара QL**. В [коде Q3](https://github.com/id-Software/Quake-III-Arena/blob/master/code/game/g_weapon.c) trace проходит 32 единицы от muzzle, а не от центра игрока; геометрия хитбокса тоже влияет. Нужна проверка QL. До неё `safe_close_contact` должен оставаться false без достоверной проверки достижимости/геометрии. Близкий промах и простое доставание оружия не генерируют реплик.

## Трупы

Изначально ответного добивания нет. `OpponentCorpseShot` допускается только как подтверждённый отдельный эпизод с ID именно трупа бота. Несколько попаданий по одному corpse_id считаются одним эпизодом. Первые два игнорируются, третий включает retaliation до конца матча и одну реплику.

После включения состояния разрешён только труп этого соперника от **последующего подтверждённого собственного убийства**. Доступность, видимость и безопасность обязаны подтверждаться адаптером. Серия ограничена `corpse_duration=1` секундой; один труп не используется повторно. Данные сбрасываются на новый матч; `forget_opponent` вызывается при отключении/смене команды.

Будущий консервативный сенсор должен подтвердить отдельную атаку после смерти, прямое попадание в конкретный труп и связь трупа с его владельцем. Смертельный выстрел, автоматическое расчленение, splash и неатрибутируемый урон исключаются. **Сейчас такого сенсора нет**; факт доступности corpse_id не означает, что намерение установлено.

## Что доступно в проверенном коде

В [WinQLX32/minqlx stats dispatcher](https://github.com/locopol/WinQLX32/blob/master/python/minqlx/_zmq.py) проверены PLAYER_DEATH, kill/death и PLAYER_SWITCHTEAM. В PlayerState — собственные health/armor/position/velocity/weapon. Готовый hook каждого удара Gauntlet или повреждения отдельного трупа не найден. Общий накопленный damage_taken этого не заменяет. Потребуется исследование собственного damage/trace hook с подтверждением attacker, target, MOD, alive-before-hit и corpse generation ID; ABI retail QL ещё не установлен.

Полное диагностическое состояние не должно передаваться в Behavior. enemy_visible требует стенового LOS, а не одного угла обзора. Идентификатор слота без поколения подключения недостаточен: слот может быть переиспользован.

## Чат и журнал

Единственный механизм сообщений — `runtime/chat.py`. Он принимает `interaction_events` из журнала C++ через `decision_record`; на сервер сообщения не отправляет. Порог эпизодов считается в C++, а не независимо второй раз в чате. При live-подключении нужен транспорт и нормализация ID соперника в Steam ID человека/ID сессии бота.

- Общий cooldown 20 секунд.
- Gauntlet: вероятность .7, тема не чаще 30 секунд, без одинаковой фразы подряд.
- Труп: приоритетная однократная реплика, срок ожидания 30 секунд, одна отложенная запись.
- Оружие/предметы: вероятность .1, общий тематический интервал 120 секунд. Видимый/слышимый pickup обязателен.
- Периодические подколы выключены (`periodic_probability=0`); каталог сохранён для будущих событийных связей.

`drain_reaction_trace()` сообщает источник события, изменение счётчиков, включение/завершение цели. `Decision.reaction_reason` объясняет попытку или отказ. `ChatPolicy.diagnostics` записывает отправку/подавление, вне игрового чата. Таймер мести проверяется в decide; отсутствие активной цели после срока не является подтверждением убийства.

## Локальная проверка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1
python -m unittest discover -s tests -v
& .\out\msvc-x64\Debug\reaction_sandbox.exe out/reactions.jsonl
python tools/replay_reactions.py out/reactions.jsonl --force-chat-for-test
```

Результат: out/reaction_chat.jsonl и отдельный diagnostics.json. Все события сценария помечены synthetic_test, команды в игру не отправляются. force-chat-for-test делает вероятность реплики 100% **только в этом воспроизведении**, без изменения штатного конфига.

После создания реальных сенсоров и исполнителя на отдельном сервере надо повторить 10 проверок из пользовательского ТЗ: выбор без удара; урон ниже/на пороге; добивание близкой видимой цели; завершение именно Gauntlet kill; 1/2/3 эпизода трупов; burst dedup; новый матч; интервалы чата. Пока серверные проверки остаются невыполненными.
