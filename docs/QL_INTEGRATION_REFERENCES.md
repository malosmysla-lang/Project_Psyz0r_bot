## QuakeLiveInterface: важный, но недоступный для скачивания кандидат

[Репозиторий](https://github.com/cainky/QuakeLiveInterface) не удалось клонировать: Git после разрешённого сетевого доступа сообщил Repository not found. Попытка codeload ZIP ветки main вернула 404. Нельзя отличить удаление, изменение адреса и ограничение доступа без дополнительного подтверждения.

Веб-инструмент показывает индексированную страницу GitHub, собранную около шести месяцев назад. Её README описывает Python-интерфейс через Redis, публикацию состояния около 60 Гц, отправку movement/attack и собственный minqlx fork с introspection сущностей. Это перспективный кандидат по описанию, но актуальный код локально отсутствует и работоспособность не подтверждена.

Пример состояния в этой копии README содержит health/armor/position соперника и точные item respawn timers. Для Psyz0r_bot нельзя напрямую считать это допустимыми наблюдениями: нужна граница между полным состоянием сервера и информацией, доступной игроку. Модель поведения должна получать только разрешённые наблюдения и память о них.

## Следующий технический разбор

Приоритет пользователя: QuakeLiveInterface → WinQLX32 → WolfcamQL. Первый остаётся кандидатом по опубликованному описанию до получения исходников; два остальных уже доступны локально. Изучаем управление, Windows/MSVC-интеграцию и извлечение данных демок соответственно.

BobbyBones — дополнительный референс: [публикация автора](https://www.reddit.com/r/quake/comments/1wyqngx/bobbybones_a_quake_live_bot_that_learns/). По переданному пользователем описанию автор заявляет обучение и сбор позиции, взгляда, клавиш и попаданий. Повторное открытие публикации 9 октября завершилось ошибкой загрузки; доступные исходники и загрузка не подтверждены. Эти заявления не считать проверенными возможностями нашего проекта. Подход Psyz0r_bot остаётся основанным на правилах.

Граница восприятия: точные HP/армор соперника и его ненаблюдаемую позицию не передавать контроллеру. Использовать видимые позиции, доступные звуковые события и оценки с неопределённостью; таймеры вести по наблюдаемому подбору. Это требование нашего адаптера, а не подтверждённая готовая функция QuakeLiveInterface.

1. Найти реально доступный интерфейс подачи usercmd/движения в выбранном расширении QL; не подменять его setter координат.
2. Сопоставить его с архитектурой Q3/Brainworks и определить минимальный адаптер нашего C++ контроллера.
3. Отдельно определить сенсорную модель без скрытых HP и точных ненаблюдаемых таймеров.
4. Для чата выбрать конкретную версию событий minqlx/minqlxtended/WinQLX32 и адаптировать сигнатуры.

Не запускались инструкции установки, отключения защит Windows, запуска серверов или рестартов из скачанных README. Материалы сохранены как референсы, не как инструкции к немедленному развёртыванию.
