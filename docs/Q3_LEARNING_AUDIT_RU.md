# Что можно перенести из Quake III learning

Проверено 25.10.2026 по открытому исходному коду id Software. Чужой код не скопирован в наш модуль; требуется учитывать upstream GPL при переносе реализации.

- [be_ai_gen.c](https://github.com/id-Software/Quake-III-Arena/blob/master/code/botlib/be_ai_gen.c): `GeneticParentsAndChildSelection` выбирает родителей и заменяемого кандидата на основе оценок популяции. Это механизм отбора, не распознавание действий человека из демо.
- [be_ai_weight.c](https://github.com/id-Software/Quake-III-Arena/blob/master/code/botlib/be_ai_weight.c): `EvolveWeightConfig` изменяет балансируемые веса; `InterbreedWeightConfigs` объединяет совместимые деревья весов. Это позволяет исследовать подбор параметров решений, но не даёт готовой распрыжки или управления мышью.

## Применимость к нашему адаптеру

Реализуемо отдельно: офлайн-подбор ограниченных весов предметов/оружия, оценка кандидатов в одинаковых матчах, откат параметров при регрессии. Для движения нужны наблюдаемые траектории, совместимая физика, корректная геометрия маршрута и проверка исполнения usercmd.

Не подтверждено: прямое подключение Q3 botlib learner к закрытому Quake Live, доступ к нужным структурам весов по проверенному ABI, самостоятельное обучение из POV. Нельзя объявлять это включённым после добавления одного cvar.

## Новый инструмент разметки

`tools/build_marked_demo_dataset.py` обработал 74 окна из 19 ранее извлечённых POV-записей. Все 74 имеют совпадение по времени и game state. Он отделяет автора POV от субъекта текстовой отметки. Отметка о хорошем движении Psyz0r не превращает движение человеческого POV в положительный пример бота. Данные пока предназначены для проверки и построения маршрутов, а не автоматического изменения live-политики.

Физические клавиши и мышь не реконструированы. Телепорты, разрывы времени, смена POV и смерть исключаются из непрерывных эталонов. Автоматически принятых положительных обучающих примеров сейчас 0.
