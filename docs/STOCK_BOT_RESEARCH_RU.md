# Штатный бот: выбор целей и пути Blood Run

Дата: 10.10.2026. Выполнен разбор реального серверного файла, а не только исходников Quake 3. Игровые файлы и работа серверов не изменены; из pak00.pk3 извлечена исследовательская копия AAS в лабораторную папку.

## Что найдено

- `baseq3/bin.pk3 → qagamex64.so`, SHA256 `091d568f46a280afbf2deda4a5ba4c8bd5e02ed6d070ef56300b1f47c5f729be`.
- Функция по смещению `0x2c920` декомпилирована angr. Псевдокод сохранён только локально: `out/research_stock_ai/goal_selection_decompiled.c`. Декомпилятор выдал предупреждения и ошибочные типы отдельных выражений; результат сверялся с дизассемблированием, его нельзя компилировать как восстановленный исходник.
- Последовательность соответствует `BotGetItemLongTermGoal` в открытом `code/game/ai_dmnet.c` Quake 3, commit `dbe4ddb10315479fc00086f08e25d968b4b43c49`: проверить верхнюю цель; проверить достижение; по истечении срока снять цель; выбрать предмет; при неудаче сбросить ограничения обхода; получить новую верхнюю цель. Продление цели на 20 секунд присутствует в бинарнике.
- Найдены строки состояний `seek LTG` и `seek NBG`. Названия функций в stripped-бинарнике восстановлены по смыслу, не по символам.

## Карта путей действительно прочитана

`baseq3/pak00.pk3 → maps/bloodrun.aas`, EAAS v5, 489600 байт.
SHA256: `c4ca730c12d02cb84758e8a6534bafadbb9f9e2dffc4efb7aa3559b851b55895`.

Наш `tools/read_stock_aas.py` читает заголовок и таблицы областей/переходов, проверяет границы блоков, размеры записей, диапазоны переходов и существование целевых областей. Получено:

- 2393 записи областей, включая служебные;
- 2724 записи reachability, включая служебную;
- 2723 направленных перехода из таблиц областей;
- типы переходов (числовые коды исходного файла): 2 — 2276; 7 — 305; 5 — 55; 18 — 20; 12 — 28; 4 — 11; 10 — 28.

Локальная копия и полный граф: `out/research_stock_ai/bloodrun.aas`, `out/research_stock_ai/bloodrun_graph.json`. В публичный Git не включены. Это сеть допустимых переходов, а не единственный заранее записанный маршрут бота. Конкретный путь зависит от цели, позиции, разрешённых перемещений и текущего состояния.

## Кандидат подключения нашей логики

Импортная таблица в данной сборке связана с `qagame + 0x2d8000`; выбор предмета вызывается через слот `0x4a0`, получение верхней цели через `0x490`, снятие через `0x468`. Семантические имена подтверждаются соответствием аргументов и последовательности с Q3, но ABI ещё не подтверждён игровым наблюдателем. Предполагаемые поля bot_state: origin `0x1314`, inventory `0x1340`, movestate `0x1964`, goalstate `0x1968`, ltg_time `0x179c`. Адреса действительны только для указанного SHA.

Нельзя переносить структуры Q3 вслепую: наблюдалось копирование цели размером 64 байта, тогда как Q3 bot_goal_t имеет другой размер. Пока не писать в память целей.

## Следующий приоритет

1. Добавить в отдельную лабораторию чтение текущей штатной цели и журнал «цель → движение → собственный подбор», без изменения выбора.
2. Проверить ABI, идентификаторы предметов и поведение на одной карте.
3. Подключить наши приоритеты ресурсов к штатному выбору целей, сохранив AAS и исполнитель движения.
4. Демки использовать для выбора более человеческих маршрутов, позиций и решений поверх рабочей базы.

Навигацию с нуля не строим. Этот этап подтверждает наличие и читаемость штатной базы; улучшение бота ещё не подключено к игре. Основной сервер не изменялся.
