# Преальфа 0.6: Blood Run, предметы и движение

Дата: 11 октября 2026. Это первая экспериментальная игровая сборка нового этапа, а не завершённый бот из всей Mind map.

## Как проверить

В консоли Quake Live: `/connect 78.17.9.235:27961`. Карта — обычный Blood Run, factory Duel. Бот занимает слот 0; после подключения можно начать матч через `/ready`. Основной сервер на 27960 не изменён.

Сначала наблюдай: выбирает ли бот полезный предмет, доходит ли до него, подбирает ли оружие после настоящего респауна, продолжает ли двигаться после неудачного подхода. Во время разминки игра может выдавать полный комплект оружия — это не подтверждение подбора оружия. Нужен начавшийся матч.

## Что подключено к игре

- Штатная навигация QL по AAS сохранена. Мы дополнили её выбором ресурсов и подходами из демок, а не заменили перемещение с нуля.
- Получена 41 проверенная цель предметов через родной интерфейс botlib. Каждая сверена по сущности, области, флагам и координатам. Неизвестные или несовпавшие цели не конструируются наугад.
- Приоритеты учитывают собственное здоровье, броню, наличие оружия, патроны, расстояние и фактическое время появления предмета. При нехватке стека усиливается приоритет жёлтой брони и лечения. Для человека-соперника используются разрешённые владельцем точные HP/armor; скрытые координаты наш модуль не читает.
- Из 100 архивных и 25 стандартных владельческих демок отобраны 257 коротких подходов к 22 предметам. Это окна подхода, а не 257 полных маршрутов по всей карте. Среди сопоставимых наблюдений выбирается самый короткий по времени вариант; глобальная оптимальность не заявляется.
- Привязка подхода идёт по классу и координатам предмета: переход FFA → Duel не ломает её из-за смены номера сущности.
- Точки подхода передаются штатному движению. Внутренняя вершина стека целей botlib синхронизируется с новой целью. При отсутствии прогресса цель временно исключается, неудачный подход получает паузу 60 секунд, бот возвращается к выбору ресурсов.
- Распрыжка включается только на достаточно прямом участке выбранного подхода, при подходящем направлении и скорости, без стрельбы. Основа — формирование направления ускорения относительно текущей скорости, а не постоянное нажатие прыжка. Частые приседания отключены.
- В банк перенесены 16 удачных эпизодов рокетджампа из `nekitz0r_ZTN_solo_01`. Используются старт, приземление, углы выстрела, задержка выстрела и наблюдавшаяся потеря HP. Перед исполнением проверяются ракеты, оружие и запас здоровья, затем выполняется разгон.
- В обычной игре разрешён только пример 0, прошедший три живых повторения. Остальные 15 сохранены для отдельных испытаний, автоматически не включены.
- Фактические подборы фиксируются после родного `Touch_Item`: проверяется исчезновение предмета или изменение оружия/патронов. Намерение подойти не выдаётся за подбор.

## Подтверждение и границы

На отдельном сервере подтверждены выбор целей, движение, подбор MegaHealth и жёлтой брони; есть подбор жёлтой брони с активным подходом из демки. Во время начавшегося матча также зарегистрирован подбор выпавшего Lightning Gun.

Для рокетджампа 0 отдельный принудительный сценарий дал три успешных повторения, затем ещё пять после обновления защиты маршрутов: первое приземление на 128–129 единиц выше старта; зарегистрированы и подборы предмета. Это проверка физического исполнения, а не доказательство надёжности выбора момента против человека. Два журнала суммированы отдельно: `PREALPHA_0_6_VALIDATION.json` и `PREALPHA_0_6_FINAL_RJ.json`.

Успешность определяется первым приземлением выше старта более чем на 8 единиц либо подбором основного предмета, аптечки или оружия во время манёвра/до 1,5 секунды после приземления. Один только высокий пик полёта, патроны и шарды успехом не считаются. Потеря HP в демке — наблюдение с возможным влиянием лечения/брони, а не точный расчёт самоповреждения.

Распрыжка исполняется настоящими командами движения; наблюдавшиеся включения записаны в `PSYZ_STRAFE`. Качество сложных поворотов и стабильный прирост скорости на всех подходах ещё требуют игрового тестирования. Некоторые подходы приводили к остановке; для них введены отказ и пауза. Все 257 подходов не объявляются проверенными.

Мышь/WASD в демке не сохранены в виде исходных нажатий: управление реконструировано. Нет заявления о полном копировании человека, минимальной возможной потере HP или полном покрытии карты.

Чат, характер, пять уровней, точность оружия, прогонка по респаунам и полная макрологика в эту преальфу не переносились. Базовый бой пока штатный Xaero skill 5. Игровой адаптер этого этапа написан на C в отдельной сборке minqlx; это не подключение всего ранее написанного C++ Behavior к retail QL.

## Для следующего разработчика

Исходники: `adapter/native/psyz_prealpha.h`, сгенерированный `psyz_bloodrun_bank.h`; банк с происхождением — `config/bloodrun_prealpha_bank.json`; генератор — `tools/build_prealpha_bank.py`. Требуются локальные разобранные демки и AAS, которые не входят в Git. Публикуются собственные извлечённые данные, не бинарники игры и не сторонние исходники.

Подготовка отдельного minqlx checkout: `tools/prepare_control_lab.py CHECKOUT --qagame QAGAME`. SHA-256 qagame проверяется до изменения checkout. Сборка Linux: `make -B -j2 nopy`. Использован minqlx commit `fbdd915185337791d8e209dc4b686a1ee60d3721`; соблюдать его лицензию при распространении производной сборки.

Тестовый home: `/home/qlserver/psyz0r-bot/prealpha-20261011/home`. Запуск — `tools/test_server_console.py`, конфигурация — `config/prealpha_test.cfg` (на сервере `psyz_test.cfg`). Запуск проверяет хеши engine/qagame. Собственный UNIX-сокет `console.sock` доступен только владельцу. `tools/prealpha_remote_cycle.py` проверяет home и порт процесса перед перезапуском; не запускать при подключённых людях.

Основные переключатели в отдельной консоли сервера:

```
set qlx_psyzPreAlpha 0  // отключить новую политику, оставить штатного бота
set qlx_psyzPreAlpha 1  // включить преальфу
set qlx_psyzRJProbe 0   // обычный выбор задач
set qlx_psyzRJProbe 1   // принудительная проверка примера RJ 0
```

Значения `qlx_psyzRJProbe` 2–16 — другие примеры, пока непроверенные. После проверки вернуть 0. Эти команды — серверные, не команды обычного клиента. Защита требует `qlx_psyzTestInstance=1`, mode 3, порт 27961 и карту bloodrun; на основном порту модуль не активируется.

Журналы: `PSYZ_TARGET`, `PSYZ_DEMO_ROUTE`, `PSYZ_PICKUP`, `PSYZ_REPATH`, `PSYZ_STRAFE`, `PSYZ_RJ_BEGIN/END`. Настоящий результат — игровое событие, а не только наличие выбранной цели. Сохранённый отчёт: `docs/training/PREALPHA_0_6_VALIDATION.json`.

Правила движения согласуются с ранее разобранными текстовыми источниками и примерами: `docs/MOVEMENT_LEARNING_GUIDE_RU.md`, `docs/GUIDE_AUDIT_2026-10-10_RU.md`. Гайды объясняют принципы, AAS обеспечивает геометрию, демки дают наблюдения, испытания подтверждают исполнение.
