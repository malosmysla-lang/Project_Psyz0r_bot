# Модуль подхода и подтверждения подбора

10.10.2026. Локальный этап; тестовый сервер не запускался.

## Данные из демки

Из 16 успешных кандидатов ZTN выделено 11 подходов с зафиксированным подбором (docs/training/ZTN_resource_approaches.json). Сохранены последовательные точки, время, скорость, взгляд, оружие, состояние земли, событие подбора и SHA исходной демки. Подходы без предметного события не выданы за ресурсные маршруты.

Позиция подхода — положение игрока в момент подбора, не вычисленная точная координата сущности предмета. Геометрия, физика и позиция требуют проверки; ready_for_execution=false. Полёт в этих подходах требует отдельного контроллера прыжка. Точки нельзя соединять напрямую и объявлять проходимым navmesh. Экспортёр этого этапа намеренно ограничен данной записью ZTN.

## Новый C++ модуль

ResourceApproach отслеживает одну уже выбранную Behavior цель. Он не дублирует выбор ресурсов и MovementController. Переходы:

1. Approach: продолжать ранее построенный маршрут к предмету.
2. AwaitPickup: по горизонтали не далее32 и по высоте не далее24, но подбор пока не доказан.
3. Complete: подтверждённое собственное событие с тем же goal_id/item_protocol_id и временем текущего этапа, не из будущего и не старше100мс.
4. Replan: предмет не подобран за1500мс после прибытия, нарушена карта/физика/доступность своего состояния, смерть либо разрыв снимков более100мс. Требуется назначение новой цели, автоматического продолжения старого решения нет.

Числа — инженерные допуски этого локального модуля, не согласованные параметры навыка или точности. Событие однозначно связывает с goal_id будущий сенсор: это контракт, не уже реализованная идентификация live сущности. На другом этаже близость XY не засчитывается. Подбор не выводится из изменения HP/оружия или из одной близости. Не проверенная позиция из демки блокирует работу до пересмотра.

## Проверено

MSVC Debug:9/9 CTest-групп, включая новый resource_pickup_progress. Сценарии: разные этажи, близость без подбора, неподтверждённое/чужое/будущее событие, подтверждение, таймаут, разрыв времени, другая физика и непроверенная позиция.

Python:20 тестов demo_learning/rocketjump audit/resource routes прошли. Проверены сохранение запретов исполнения, разрыв сегмента/времени, исключение неудачных кандидатов. Найденная тестом проблема неупорядоченных снимков исправлена: экспорт не принимает такой поток.

## Следующая проверяемая ступень

Связать одобренный подход с существующим MovementController и native-исполнителем; получить собственные события подбора через live-сенсор. До этого новый модуль работает в локальных тестах, а 11 маршрутов являются наблюдениями для проверки. Следом выбор оружия из фактического инвентаря и проверка смены оружия, затем один RJ по демке. Игровое исполнение и запуск сервера — отдельным этапом по команде владельца.
