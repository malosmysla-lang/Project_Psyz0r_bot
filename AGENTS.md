# Правила работы над Psyz0r_bot

Пользователь требует вести все дальнейшие этапы разработки в GitHub как открытый проект. После каждого законченного этапа обновлять CHANGELOG.md и PROJECT_STATE.md, выполнять соответствующие проверки и создавать отдельный Git-коммит. При настроенном удалённом репозитории отправлять завершённый этап в GitHub в рамках этого разрешения. Если удалённый репозиторий недоступен, сохранять локальный коммит и прямо сообщать, что публикация не выполнена.

Не реконструировать историю прошлых версий выдуманными коммитами. Не включать references исходники, assets, демки, UDT бинарники, сборки и секреты. Публиковать сведения об источниках и точные версии отдельно. Чужие материалы не получают лицензию нашего кода автоматически.

Основная суть и ограничения без WH — README.md и SPEC.md. Отличать работающую политику решений от неподтверждённых игровых сенсоров/исполнения.

Последнее ТЗ владельца (2026-10-09, docs/NEW_REQUIREMENTS_RU.md): разработка локальная; развёртывание и игровые испытания только по отдельной команде владельца. Это заменяет разрешение предыдущего серверного этапа; ранее запущенный экземпляр не изменять в рамках локальной работы. Раздел 14 разрешает однократное предложение реванша после финала, но не новые команды кика/приглашения. Точность по уровням согласовать до применения. Разработку вести в Project_Psyz0r_bot, сохраняя штатного бота и его жизненный цикл. Не записывать секреты в документацию/Git. При новой команде серверного этапа сохранять резервные копии изменяемых файлов и действовать только в её пределах.

Кодирование — по отдельной команде; не менять исходники/исполнительные конфиги и не запускать сборки/сервер автоматически.
